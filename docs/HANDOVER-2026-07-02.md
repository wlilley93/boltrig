## 6. Settings/admin coverage gap (Beat 5 chunks 3+, the spec)

The user asked "are we exposing every setting variant in a nice way?" Answer:
no, on two axes. Per-user coverage is complete but presentation lags; admin is
behind; several sections have no UI at all.

Exposed but not best-in-class:
- The entire Admin console is **eight raw JSON textareas** (privacy, network,
  HITL, models, memory, ...) validated only by `JSON.parse`.
- Appearance toggles (reduced-motion, high-contrast) are yes/no dropdowns, not
  switches.
- A user's permission scope is edited as a raw JSON blob in the org tab.
- Minted token secrets use a hand-rolled box; destructive actions use browser
  `window.confirm` popups (5 places).
- Admin config writes bypass the governed request-change/approval path that
  Agents and Automations now use.

No UI at all (server lets an admin edit any manifest section; UI hard-codes 8):
identity/role mappings (the actual RBAC source of truth), the org hierarchy
including budgets (read-only everywhere, editable nowhere), spawn rules, adapter
config, runtimes, MCP, chat settings, org-level defaults. **Channels have full
CRUD on the backend and zero UI** - the single biggest gap.

Legitimately operator-only and correctly kept out: deploy-time env (ports,
secrets, OIDC wiring, backups).

The design system already ships the right primitives (typed schema forms,
switches, segmented controls, a scope builder with live preview, a guarded
one-time secret reveal, in-frame confirm, the governed save bar) - Settings and
Admin just predate them. The beat is coverage-and-quality, not cosmetic.

## 9. Self-improvement program (the "make everything self-improving" answer)

Every organ exists; the closed circuit is not wired. In order of value:
1. Land the learning loop (the foreign WIP) - outcomes + lessons are the raw
   material for everything else.
2. Reflection -> memory -> future behavior: lessons written through
   `memory.remember`, recalled into task composition.
3. Eval-gated promotion: generated workflows become candidates, pass an eval
   suite, then promote (and demote on later failure). Turns EvalRunner from QA
   into the immune system.
4. Harvest free signals: a regenerate `superseded_by` marker is a negative
   signal; HITL approvals/rejections are endorsement/block signals. Pipe both
   into `memory.improve` and outcome scores. No new UI.
5. Selection loops over models and skills (the manifest carries multiple
   endpoints; route to what measurably works per task class).
6. Turn the substrate on: Hatchet (now live on this box), `evaluation.enabled`
   with real suites, Cognee for semantic memory + its reweighting leg.

Non-negotiable rail: the loop may improve competence, never authority. Learned
workflows run under the same grant ceilings as authored ones; `memory.improve`
already cannot touch scope. Pin "self-improvement never widens authority" in
`tests/invariants.yaml` and rule it at court before the loop closes (S5 fork).
