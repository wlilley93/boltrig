# Boltrig Security Audit - 2026-07-02

Commit audited: c4c80c6. Method: agents-final security-suite full-security-audit playbook (standalone mode), six parallel surface finders, every HIGH adversarially verified by inline re-read. Threat model: external attacker, insider, lower-privilege end user, prompt injection via channels/memory/tool-results. Out of scope (marked INFO where reached): PyPI publishing-pipeline compromise, cloud control-plane compromise, physical access, trusted-infrastructure queue-write.

## Executive summary

Boltrig's security posture is strong where it matters most: the credential vault never leaks a resolved key to an agent (crown-jewel invariant, traced through every `.material` call site and the durable-task envelope), the dispatch chokepoint has no execution-primitive bypass, tenant isolation is complete on every store query, the OIDC/CF-Access identity layer is fail-closed with alg pinning and correct audience checks, and the container hardening (read-only, cap-drop, no-new-privileges, internal networks) is real. The defects are cracks in specific gate mechanisms, not a soft core.

Five HIGH findings, all confirmed, all in governance/availability-integrity paths (not data exposure): a human-approval gate an agent can clear without a human, an SSRF rebinding gap that defeats the egress guard's own stated guarantee, a tamper-evident audit key that silently defaults on the worker, a "hard-stop" budget that does not stop under concurrency, and the project's own invariant gate red in CI on every commit. Fourteen MEDIUM and roughly fifteen LOW/INFO findings follow.

## Findings ranked by exploitation risk (Section 11)

### H1 [HIGH] HITL human-approval gate is agent-clearable via a null-verb, non-APPROVAL request
`boltrig/kernel/hitl.py:141`, `boltrig/kernel/app.py:420`, `boltrig/kernel/dispatch.py:203-223`
`consume_if_approved` returns True for any ANSWERED request with an approving decision, skips the verb match when `req.verb is None`, and never requires `req.type == APPROVAL`. The respond route applies the human-tier and anti-self-approval guards ONLY when `req.type == HITLType.APPROVAL`; escalation and clarification requests (which the fleet creates with `verb=None`) can be answered by a non-human tier and by the requester. So an actor that can answer a null-verb escalation with "approve" can pass its id as `approval_id` to any HIGH-consequence verb and clear the gate - no human, no verb binding. The dispatch comment "cannot be bypassed by an agent" is false.
- Exploit: (pre) a null-verb escalation/clarification exists in the tenant, answerable by the actor; (action) answer "approve", replay its id as `approval_id` on a high-consequence verb; (blast) the human-in-the-loop guarantee - the product's core trust claim - is void for that verb.
- Fix: in `consume_if_approved` require `req.type == HITLType.APPROVAL` and fail closed when `req.verb is None` (never skip the verb match); extend the respond-route human-tier + anti-self-approval guards to every consumable request type. Test: `test_escalation_answer_cannot_clear_high_consequence_gate`.
- Verification required: confirm no legitimate flow consumes a null-verb APPROVAL (dispatch always sets verb, so the tightening is safe). Residual: only a genuine, verb-bound, human-answered APPROVAL clears the gate.

### H2 [HIGH] SSRF: egress guard resolves-then-connects (DNS-rebinding TOCTOU), no IP pinning
`boltrig/adapters/egress.py:122-128`, `boltrig/adapters/builtin/web_fetch.py`, `channel_send.py`, `mcp_consumer.py`
`assert_egress_allowed` resolves the host once, vets those IPs, then hands the raw URL to httpx, which resolves again at connect time. No client pins the vetted IP. A low-TTL attacker domain returns a public IP to the guard and 169.254.169.254 (or 127.0.0.1 / RFC1918) to httpx. `web.fetch` is agent-supplied and consequence=high, but the HITL approver only sees the benign hostname; the rebind flips after approval. `channel.send` outbound_url and the MCP-consumer URL (which carries a bearer) share the gap. The egress module docstring claims rebinding "is still refused" - contradicted by the implementation.
- Exploit: (pre) attacker-controlled low-TTL domain, an agent/admin fetch of that URL; (action) guard sees public, httpx connects to internal; (blast) cloud-metadata credential theft / internal service reach / bearer leak to internal space.
- Fix: resolve once, vet every returned IP, then connect to the pinned IP literal via a custom httpx transport with Host+SNI preserved (block IPv6/alternate records too). Test: `test_egress_rejects_dns_rebind_between_check_and_connect`.

### H3 [HIGH] Tamper-evident audit key silently defaults on the worker / unsignaled boot
`boltrig/kernel/audit.py:23`, `boltrig/api/bootstrap.py:243-258,310-334`, `boltrig/api/worker.py`, `boltrig/fleet/hatchet_app.py`
`_HMAC_KEY` defaults to the in-source `dev-insecure-audit-key`. The guard `refuse_default_audit_key_in_prod()` runs only in `create_app` (bootstrap.py:334); `build_kernel_async()` - the path the fleet worker and Hatchet worker use - never calls it, and the guard fires only under a production-signal env var that the shipped compose does not set. A production worker missing `BOLTRIG_AUDIT_HMAC_KEY` boots silently with the public default and writes forgeable audit rows for exactly the unattended pump/durable actions, and forks the per-tenant hash chain so `verify()` reports corruption against the API's real key.
- Fix: call `refuse_default_audit_key_in_prod()` inside `build_kernel_async()` (every audit-writing process), and drive the key from settings into `AuditWriter` rather than a module-level env read. Default the shipped deployment to a prod posture. Test: `test_worker_boot_refuses_default_audit_key_under_prod_signal`.

### H4 [HIGH] Budget hard-stop bypass under concurrency: reserve() discards consume_budget()'s refusal
`boltrig/kernel/cost.py:66-69`, `boltrig/store/postgres.py` consume_budget, `boltrig/fleet/spawn.py:266-288`
`reserve()` fail-fasts on an unlocked `get_budget` read, then loops `await consume_budget(...)` and ignores the boolean return. `consume_budget` is atomic (FOR UPDATE, re-checks the limit, returns False without debiting when a hard-stop would be exceeded). Two concurrent spawns both pass the read, both call consume: the first debits, the second is refused-but-ignored and runs anyway, unmetered past the cap. The same ignored return voids the module's all-or-nothing claim.
- Fix: capture the return; if any scope refuses, compensate the debited scopes (or run the multi-scope reserve in one transaction with FOR UPDATE) and raise BudgetExceeded. Test: `test_concurrent_reserves_cannot_exceed_hardstop`. (Reasonable reviewers could call this Medium - it is a cost/availability control, not an auth boundary - but a "hard stop" that does not stop is a broken guarantee, so HIGH.)

### H5 [HIGH] The invariant gate is red in CI on every commit and unenforced
`.github/workflows/ci.yml`, verified via `gh run list` (last 5 main pushes all "failure")
CI is not billing-blocked (contrary to the repo docs); it runs and fails every time. Root cause: the CI Postgres service image lacks the `pgvector` extension (`asyncpg ... extension "vector" is not available`), so every `[postgres]`-marked test errors at setup and the "Test suite + invariant gate" job is red. Commits merge to main regardless, so the machine-checked gate the project relies on to catch regressions in tenant isolation, the audit chain, and grant checks has never actually passed in CI.
- Fix: use `pgvector/pgvector:pg16` as the CI Postgres service image (matches the local test container); add branch protection requiring the check. Test: the gate job goes green. One-line change, highest leverage.

## Medium findings (deduplicated)

- M1 [MED, structural] Untrusted text (external-MCP/web.fetch tool results, the continuity transcript, memory recall, channel inbound) is concatenated into prompts with no untrusted-envelope tags; the only screen (`screen_content`) is memory-ingest-only and defeated by leetspeak/reorder/zero-width/base64/non-English (5 working bypasses). Held below HIGH only because destructive verbs stay HITL-gated. Fix must be structural: typed `<untrusted-...>` delimiters at composition + a governance-floor assertion that tagged content is data. `services/pi_sidecar/app.py:430-438`, `boltrig/fleet/continuity.py`, `boltrig/memory/adapter.py:57`.
- M2 [MED] Pi sidecar `POST /run` is unauthenticated and issues server-side requests to caller-supplied `mcp.url` / `model.endpoint` with no egress guard - an SSRF pivot from the sidecar's network position. Fix: apply the egress guard in the sidecar + require a shared secret/mTLS on `/run`. `services/pi_sidecar/app.py:500-507`.
- M3 [MED] Webhook replay: the `t=` timestamp is not bound into the HMAC and there is no delivery-id dedup, so a captured signed request replays with a rewritten timestamp and mints duplicate work items. Fix: HMAC over `t + '.' + body`, require a timestamp, dedup on (channel, external_id). `boltrig/adapters/builtin/inbound_webhook.py:134-146`.
- M4 [MED] A webhook channel created without a signing secret accepts unauthenticated inbound; the only guard is the unguessable channel_id (a bearer if it leaks). Fix: require a secret for webhook-transport channels unless an explicit audited `unauthenticated` flag is set. `boltrig/kernel/channel_routes.py:142-153`.
- M5 [MED] Inbound channel intake has no rate limit and no per-tenant fairness; each request creates a work item that can drive model spend. Fix: per-channel and per-(channel,sender) intake limit + per-tenant intake budget. `boltrig/kernel/channel_routes.py:134-198`.
- M6 [MED] Body-size cap checks Content-Length only; a chunked request with no length bypasses it. Fix: enforce on the streamed byte count. `boltrig/kernel/web_security.py:62-79`.
- M7 [MED] `list_work_items` has no LIMIT/pagination; `/v1/work` returns the whole slice and `/v1/work/{id}` is O(all visible items) per call. Fix: keyset pagination + query children by parent_id. `boltrig/store/postgres.py:421-437`.
- M8 [MED] Hatchet engine (gRPC :7077 plaintext), API :8888, and the unauthenticated dashboard :8889 publish on 0.0.0.0 with insecure cookies, and the secure overlay does not override them. Fix: bind to 127.0.0.1 or drop the published ports; add `ports: []` in `deploy/compose.secure.yml`. `docker-compose.yml:137-174`.
- M9 [MED] Default DB creds `boltrig:boltrig` are baked into compose and the Hatchet DSN. Bounded because Postgres publishes no host port, but combined with M8 becomes reachable. Fix: drop the password default so the stack refuses to start without POSTGRES_PASSWORD. `docker-compose.yml:43-45,144`.
- M10 [MED] No automated or off-box backup ships; backup is a manual same-host `pg_dump`. For a self-hosted product with a durable audit chain this is the backup-criticality gap. Fix: a scheduled pg_dump sidecar + off-box encrypted copy + restore verification. `docs/backup-restore.md`.
- M11 [MED] Right-to-erasure is partial: `DELETE /v1/me/conversations/{id}` soft-closes (status=CLOSED) and the hard-purge retention job does not ship, so conversation bodies persist. Memory facts DO hard-erase. Fix: ship the purge worker. `boltrig/kernel/access_routes.py:132-145`.
- M12 [MED] The secret-detection pattern set (`contains_secret`) is narrow (misses PEM keys, `AIza...`, `xox[baprs]-...`, `sk_live_...`, high-entropy blobs) and backs BOTH the audit scrub and the memory-ingest guard, so an unrecognised secret persists into memory and audit previews. Fix: broaden patterns + an entropy fallback. `boltrig/kernel/pii.py:25-31`.
- M13 [MED] The manifest advertises a `saml` identity provider that is entirely inert (`SamlVerifier.verify` raises NotImplementedError; resolver selection never reads it), so an operator can believe SAML is enforced when the deployment silently runs env-selected auth. Fails closed (no bypass) but is a governance gap. Fix: remove `saml` from the enum or hard-fail on it. `boltrig/identity/auth.py:166-191`.
- M14 [MED] Budget is enforced only at spawn against a char-count estimate, never inside `invoke` per-verb and never reconciled against the model's actual returned token usage, so a small task with a long tool-loop overspends. (Overlaps engine-plan Phase 5 cost true-up.) `boltrig/fleet/spawn.py:173-178,256-269`.
