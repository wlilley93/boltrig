# 0021 - Worker primary surface and scoped realtime voice

- Status: accepted
- Date: 2026-07-28
- Amends: 0004 (spatial deck presentation) and 0012 (target runtimes)
- Baseline: `andrewyng/openworker@f96ad4c8e6865f0aec519681a3717b6bcdd81546`

## Context

Boltrig needs a friendly task-oriented client. OpenWorker provides an MIT-licensed
React/Tauri presentation baseline,
but its local Python agent, model clients, connector credentials, permission
engine, memory, and scheduler would duplicate Boltrig authority and create side
doors around the dispatcher.

Voice calls additionally need a low-latency dialogue runtime. Decision 0012 made
Codex the only target agent runtime. A realtime speech session is a different,
bounded role: it carries media and dialogue but must not become another
authority, workflow engine, connector host, or general tool runtime.

## Decision

Boltrig supports one first-party client over one governed HTTP/event contract:

- **Worker** is the primary web route and the payload packaged by Tauri. It owns
  task-oriented presentation: conversations, inbox, composer, transcript,
  artifacts, integrations, automation entry points, Familiar presence, and
  native user-initiated affordances.
The spatial deck from decision 0004 is retired with the former Operator client,
not a universal frontend requirement.

Worker consumes `@wlilley93/boltrig-web-sdk` types and event normalisation. It
does not own authority, credentials, connector execution,
workflow state, memory truth, artifacts, or model routing. A frontend may render
an SDK contract before its server capability is enabled, but it must show a
typed unavailable or uncertified state rather than claim the seam is working.

Certified manual integration setup is provider-declared data, never a generic
secret bucket. A versioned closed contract names the only accepted bounded
fields and the non-secret account labels. Worker submits that exact form once;
the kernel seals the values directly into an adapter-scoped credential
reference and returns only connection/account metadata. Undeclared fields,
uncertified providers, and OAuth providers without a reviewed exchange contract
remain unavailable.

The OpenWorker commit named above is a one-time source baseline. Boltrig retains
its MIT notice in `THIRD_PARTY_NOTICES.md`, rebrands the code, removes the
OpenWorker server and cloud dependencies, and accepts later upstream changes
only by reviewed selective import.

Worker is the sole first-party browser surface. It is the default presentation.
Caddy proxies the
Worker image directly; there is no separate frontend image, overlay or browser
path to maintain. Removing the retired presentation did not change kernel or
tenant state.

## Realtime voice exception

Decision 0012 is amended by exactly one target-runtime exception named
`realtime_voice`.

1. The exception conducts live dialogue and requests only function tools
   generated by the Boltrig kernel for the current run.
2. Every requested tool re-enters the ordinary dispatcher and its fixed
   validation, grant, HITL, rate-limit, credential, execution, output-validation,
   and audit sequence. The provider receives no integration credential.
3. Provider-native search, remote MCP, code execution, and other provider-hosted
   tools are forbidden. `realtime_voice` cannot spawn agents or own workflows.
4. The first adapter is xAI Realtime behind the channel gateway. It is a seam
   until fake-provider and credentialed staging acceptance pass.
5. Browser and desktop clients receive only short-lived media/session tokens.
   Permanent provider credentials stay server-side.
6. Boltrig persists transcript, normalized events, usage, and call metadata.
   Raw microphone or synthesized audio is neither persisted nor logged.
7. A pending tool approval parks the exact call through the held-call/HITL
   mechanism; approval resumes that call rather than constructing a wider one.
8. Unavailability returns a typed `realtime_unavailable` state and offers
   continuation in the existing Codex text conversation. It never falls through
   to a legacy agent runtime.

## Desktop device boundary

The Tauri shell is an enrolled outbound device, not a local agent server.
Device file and optional command capabilities are registered as ordinary
adapter data. Calls use signed, expiring, scoped, single-use leases minted only
after dispatcher/HITL admission. Paths use `root_id + relative_path`; command
execution is disabled by default and each invocation requires explicit
approval. Native open, reveal, and save actions are user-initiated
materialisation of an authorized artifact download, never an agent side door.

## Cutover and honesty

Worker is the root route. Connector certification, device and call acceptance,
accessibility and browser/Tauri acceptance remain independently governed gates;
the deployment must describe Worker, device execution, connectors and realtime
voice by their actual enabled/certified state.

## Removal record, 2026-08-10

The former Operator client was removed from the repository and deployment. Worker
now serves the root presentation on local, development and production stacks;
there is no second browser client or retired-client fallback path. This removal
changed presentation packaging only and did not alter kernel or tenant state.
